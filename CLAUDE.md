## What this repo is

A compact prompt-injection text classifier with no LLM, built to scan retrieved RAG chunks,
web-search results, and uploaded files inside Open WebUI before they reach the model, and to be
importable from any Python app. Repo: https://github.com/beaudamore/prompt-injection-nn

It mirrors https://github.com/beaudamore/email-classifier-nn phase for phase. When in doubt about
pipeline structure, notebook conventions, or evaluation, look at how the email repo does it.

It complements, not replaces, the prompt-injection LoRA in https://github.com/beaudamore/safety.
The LoRA (Qwen3.8-27B, served from the Spark's vLLM stack) handles typed chat prompts through
the existing inlet filter. This model handles the retrieval path, where one turn can carry ten or
more chunks and an LLM call per chunk is too slow.

**Changed 2026-11-05:** the owner is dropping the LLM/LoRA-based typed-prompt filter. Typed prompts are
now covered from this repo too, by a second filter that uses the same guard service (see "Two filters"
under Where things stand).

  - **0.5.0 (2026-11-05): the same filter also scans attached files at send.** Decided by the owner: no third filter; the upload scan is an `inlet` hook in the retrieved-content filter (file name, title and logger unchanged for now). Open WebUI runs no filter at upload time, so `inlet` is the earliest point. It scores the whole stored text (`Files.get_file_by_id`, `data["content"]`) of every item of type `file` in `body["metadata"]["files"]` (the same id once) that the sending user may read (admin, owner, or `has_access_to_file(id, 'read', user)` on the record from `Users.get_user_by_id`; no user or user not found means the scan is not active that turn); in enforce mode a flagged file blocks the turn and is named with its score (`block_mode`, `block_message`), and `delete_flagged_files` (default False) deletes it for an admin, the owner or a user with `'write'` access: file record first, then the stored file (best effort); knowledge-base links, knowledge-base chunks and the `file-<id>` collection are not removed. Each file is scored on its own, one guard call per group of up to 64 pieces; the seconds spent in failed calls are added up over the turn, and once they reach `FAILED_CALL_TIMEOUTS` (2) x `timeout_s` (60 s at the default) the rest of the turn passes unscanned (a call that fails at once uses up next to nothing) and files not fully scored are reported (`UNSCANNED`, `PARTLY SCANNED`, `incomplete=`). Which files are in that list (model knowledge files, chat folders) is an open decision for the owner: `filter/README.md`. No violation count, lockout, webhook or violation knowledge base. Fails open with a warning; the hook's own errors never end a turn. New valves: `scan_uploaded_files` (True), `block_mode`, `block_message`, `delete_flagged_files`; one `log_only` and one `priority` (-50) for both hooks. The filter is now block-aware (`FILTER_BLOCK_AWARE = True`): its `inlet` runs after the antivirus (-200) and chat (-100) filters and always finalizes a recorded block when it is the last block-aware filter, whatever its valves say. The `request` hook's code is unchanged and never blocks. Open WebUI 0.13.0 sends the chat's attachments again on every turn, so each file is re-scored every turn (no cache, by decision). **Not run live; the copy installed in Open WebUI is still 0.4.1 until the owner has it updated.** Log lines: `upload ...` per turn, `file ...` per file.

## Conventions that matter

- **Output contract is fixed:** `SAFE` or `INJECTION: <reason>` with one of the nine reasons in `docs/PLAN.md` §1. The filter and the LoRA depend on it. Exception since 2026-11-05: the chat filter reports `Prompt injection (guard score <p>, threshold <t>)` because the guard gives no taxonomy reason.
- **Open WebUI integration is filters only, no patch:** a `request`-hook filter for retrieved content (since 0.5.0, 2026-11-05, with an `inlet` hook for files attached at send) and, since 2026-11-05, an `inlet`-hook filter for typed prompts. The reasoning and the verified pipeline order are in `docs/PLAN.md` §5. Do not propose patching Open WebUI unless the user asks.
- **Notebooks are committed with outputs. LF line endings, `indent=1`.** Use the `notebook-editing` skill.
- **Holdout discipline.** `train` fits; `val` selects; `test` and `adversarial_test` are opened once. The LoRA's held-out sets (WildGuardMix `wildguardtest`, Nemotron held-out `jailbreaking`) are the comparison set and are never trained on.
- **Every run records provenance** in a manifest tied to the dataset fingerprint.
- **The data contains live attack strings.** Never paste them into a real model session outside the notebooks.
- **Do not commit or push unless the user asks.** State the exact change before making it.
